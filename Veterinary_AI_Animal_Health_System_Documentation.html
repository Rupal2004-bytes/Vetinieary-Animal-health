1. Executive Summary & System Overview

The VetMyPet - AI Animal Health & Diagnostic Platform is a full-stack, multimodal clinical decision support system engineered for veterinary practitioners, veterinary technicians, agricultural livestock managers, and companion animal owners. The system ingests high-resolution still photographs and temporal live video recordings (e.g. motion, involuntary spasms, chorea, gait abnormalities, respiratory distress), extracts sequential keyframes, conducts objective computer vision inspection, and synthesizes visual evidence with owner-reported clinical history using specialized Large Multimodal Models (LMMs).

Unlike conventional veterinary AI classifiers that rigidly classify dermatology lesions or force single disease predictions, this platform operates on an unbiased, broad-spectrum differential diagnosis framework. It evaluates infectious (viral, bacterial, fungal, parasitic), non-infectious (mechanical obstructions, toxicological, inflammatory, metabolic, traumatic), and behavioral presentations across canine, feline, bovine, equine, caprine, ovine, and avian species using viggovet/viggoVet-Reasoning-20B for veterinary clinical reasoning.

2. Problem Statement & Key Industry Challenges

Veterinary triage and diagnostics face significant operational and technical hurdles:

  • The Static Image Diagnostic Blindspot: Many life-threatening veterinary conditions cannot be diagnosed from a single static photograph. For example, Canine Distemper Virus (CDV) presents with rhythmic chorea/myoclonus (jaw and leg twitching), Equine Colic presents with dynamic visceral pain (ground pawing, flank watching, rolling), and Rabies presents with behavioral agitation or ataxia. These require motion analysis across temporal video frames.
  • Classifier Bias & False Positives: Traditional image classification models are trained on narrow dermatological datasets, frequently misclassifying critical systemic emergency conditions (e.g. Parvovirus, Distemper, AHDS) as superficial skin pyoderma or forcing predetermined diseases.
  • Data Integrity & Concurrency Lockouts: In embedded database deployments (e.g. SQLite in veterinary clinics and field laptops), continuous automated snapshot backups frequently trigger database is locked errors during write-heavy clinical screening workflows.
  • Auth Header & API Token Collisions: In multi-tier architectures, forwarding user login bearer tokens into third-party AI provider headers triggers HTTP 401/403 authorization rejections.

3. Our Solution & Core Innovations

🎬 Multimodal Video & Keyframe Pipeline

In-browser camera recording (MediaRecorder) and file upload (.mp4, .webm, .mov) with automated ffmpeg temporal sampling extracting 4 evenly-spaced keyframes across timeline adhering to AI router quotas.

🧠 Dual-Stage Multimodal AI Pipeline

Strict separation of concerns: Stage 1 (Qwen2.5-VL-72B-Instruct) performs purely objective visual/motion extraction; Stage 2 (viggovet/viggoVet-Reasoning-20B) executes specialized veterinary internal medicine reasoning.

🔒 Dual-Database & Point-in-Time Backups

Dedicated user.db (Bcrypt password hashing, token auth) and animal_health.db (records, media, screenings) with automatic VACUUM INTO point-in-time snapshot rotation upon every database mutation.

⚡ Lock-Free SQLite Concurrency

WAL mode with _busy_timeout=10000, PRAGMA busy_timeout = 10000;, and serialized write pooling (SetMaxOpenConns(1)) completely eliminating lock contention during simultaneous auto-backups.

6. Detailed In-Depth Pipeline Mechanics

6.1. Temporal Video Keyframe Extraction & Quota Compliance

Modern Multimodal LLM endpoints (e.g. Hugging Face Router for Qwen2.5-VL-72B-Instruct) enforce strict limits of at most 5 images per request prompt. Videos recorded in browsers or uploaded from phones often contain hundreds of frames at 30–60 FPS.

The backend implements adaptive temporal sampling in backend/internal/ai/providers.go: 

// Extract 4 representative temporal keyframes across the video using ffmpeg
// Enforces max 5 image quota constraint on the multimodal inference router
cmd := exec.CommandContext(ctx, "ffmpeg", "-y", "-i", cleanPath, 
    "-vf", "fps=1/2,scale=512:-1", "-vframes", "4", framePattern)
if err := cmd.Run(); err == nil {
    files, _ := filepath.Glob(filepath.Join(tmpDir, "frame_*.jpg"))
    sort.Strings(files)
    for _, f := range files {
        data, _ := os.ReadFile(f)
        frames = append(frames, "data:image/jpeg;base64," + base64.StdEncoding.EncodeToString(data))
        if len(frames) >= 4 { break }
    }
}

6.2. Unbiased Dual-Stage Clinical AI Reasoning

To ensure the AI evaluates cases on a true medical spectrum without artificial disease hallucinations or forced diagnoses:

  • Stage 1 (Vision): Strictly extracts physical abnormalities (e.g. *"lateral recumbency, bandaged right front paw, fluid/hematochezia stain near perineum, no voluntary movement"*). No disease names are injected into the prompt.
  • Stage 2 (Veterinary Reasoning): Evaluates evidence across infectious (viral, bacterial, parasitic), mechanical (foreign bodies, obstructions), toxicological, inflammatory, and metabolic categories using viggovet/viggoVet-Reasoning-20B.
💡 Unbiased Diagnostic Guidelines (System Prompt)
"1. UNBIASED EVALUATION: Formulate differentials based purely on patient species, reported complaints, and visual findings.
2. COMPREHENSIVE SPECTRUM: Systematically consider all relevant etiologies across infectious (viral, bacterial, fungal, parasitic), mechanical/surgical (obstructions, trauma), toxicological, inflammatory, and metabolic disorders.
3. EVIDENCE-BASED RANKING: Provide 4-5 differential diagnoses ranked by true clinical likelihood with pathophysiological reasoning.
4. DIAGNOSTIC WORKUP & TRIAGE: Recommend specific confirmatory lab tests, imaging modalities, and immediate emergency management."

6.3. Concurrency Resilience & Lock-Free SQLite WAL Setup

To allow concurrent read operations, write operations, and background snapshot auto-backups without database is locked exceptions, the SQLite connections are configured with explicit busy timeouts and single-writer pooling: 

// Connection string with busy timeout and WAL journal mode
db, err := sql.Open("sqlite3", path + "?_foreign_keys=on&_journal_mode=WAL&_busy_timeout=10000")
db.SetMaxOpenConns(1)
db.Exec(`PRAGMA foreign_keys = ON; PRAGMA journal_mode = WAL; PRAGMA busy_timeout = 10000;`)

9. Security Architecture & Reliability Engineering

🛡️ Security & Zero-Leakage Architecture
  • Header Isolation: User session tokens are strictly passed over X-Auth-Token and X-User-ID headers. The server's AI client injects the upstream Hugging Face API key independently via Authorization: Bearer <HUGGINGFACE_API_KEY>, preventing session token leaks and 401 collisions.
  • No Public Admin Endpoints: All database inspection, health checks (PRAGMA integrity_check), and automated backup triggers are strictly internal to the server process and are never exposed to the public Internet.
  • Bcrypt Password Security: User passwords in user.db are salted and hashed using adaptive Bcrypt (cost factor 10). Plaintext passwords are never stored in memory or on disk.
  • Atomic Point-in-Time Backups: The backup engine uses native transactional VACUUM INTO commands, producing zero-downtime, fully verified, uncorrupted backup snapshots in ./backups/ upon every database mutation.
